# CRM UUIDv7 ID Policy

## Status

Effective for all **new CRM tables and new CRM domains** created after this policy.

Existing rows and existing primary keys are not rewritten.

## Rules

1. New primary keys use **UUIDv7**.
2. Existing UUID primary keys remain unchanged unless a separate migration is explicitly approved.
3. Business chronology is always based on `created_at` / `createdAt`, not UUID ordering.
4. UUIDv7 is generated in the application before the database insert.
5. New Prisma models should not use `@default(uuid())` for their primary key.
6. New records must pass an explicit UUIDv7 value generated by `generateUuidV7()`.
7. Foreign-key columns remain PostgreSQL `uuid`.
8. Bulk imports, backfills, and system-created records that create new entities must use the same UUIDv7 generator.
9. Do not infer business dates from the UUID timestamp. The UUID timestamp represents ID generation time only.
10. Within the same millisecond, UUID lexical order is not guaranteed to equal creation order. Use `created_at` for deterministic ordering.

## Prisma pattern

Use:

```prisma
model ExampleEntity {
  id        String   @id @db.Uuid
  createdAt DateTime @default(now()) @map("created_at") @db.Timestamptz(3)
  updatedAt DateTime @updatedAt @map("updated_at") @db.Timestamptz(3)
}
```

Do not use for new models:

```prisma
id String @id @default(uuid()) @db.Uuid
```

## Create pattern

```ts
import { generateUuidV7 } from "@/lib/server/uuidv7";

await prisma.exampleEntity.create({
  data: {
    id: generateUuidV7(),
    // ...
  },
});
```

## Existing CRM models

Existing models such as Company, Deal, Task, DeliveryProject, and other current tables keep their current IDs.

This policy applies when adding new models such as future Clinic Lead, Lead Campaign, External Source Link, AIOS event/execution integration tables, and other newly introduced domains.

## Why created_at remains authoritative

UUIDv7 improves index locality and gives IDs a time-ordered prefix, but it is still an identifier. Application screens, KPI calculations, exports, audits, and chronological queries must continue to use explicit timestamp columns.

## Implementation

Server-side generator:

`src/lib/server/uuidv7.ts`

The implementation follows RFC 9562 UUIDv7 layout:
- 48-bit Unix epoch timestamp in milliseconds
- version = 7
- RFC variant = 10xx
- remaining bits are cryptographically random
